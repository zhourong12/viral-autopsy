# 爆款解剖室 · Viral Autopsy

> 把你自己发过的内容数据交给它：AI 提出“为什么这篇爆了”的猜想，统计检验来当法官。真规律留下，巧合埋进“玄学墓地”，再给你开一张下几篇的实验处方。

创作者最焦虑的是“下一篇写什么、怎么写才会火”。平台数据中心只给数字，不给原因；直接把表格丢给 AI，它会很自信地总结出几条规律。可是样本只有几十篇、账号还在涨粉、一篇爆文就能拉高平均数，这些“规律”大多经不起检验。

爆款解剖室支持小红书、抖音、B 站、公众号和 YouTube。它用你自己的数据逐条检验 20 条圈内流传的爆款说法，再加上 AI 针对你账号提出的猜想，最后告诉你哪些成立、哪些存疑、哪些还看不出来、哪些该放下，以及接下来怎么验证。

## 它和“让 AI 帮我分析数据”有什么不同

|                    | 爆款解剖室                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| **AI 不做算术**    | 所有数字由代码计算。AI 只负责读截图（照抄文字，换算在代码里做）、贴标签、提猜想和写总结。                   |
| **AI 不决定真假**  | 判决只看统计检验。AI 提出的猜想和 20 条常见说法放在一起，统一做多重比较校正。                               |
| **扣除涨粉影响**   | 每篇只和前后各 5 篇比，而不是和全部内容的平均比。涨粉期发的内容不会白白占便宜。                             |
| **识破单篇爆文**   | 去掉最火的一篇再算一次；规律消失就进墓地，死因写“一篇爆文撑起来的”。                                        |
| **诚实说“不知道”** | 每组不到 5 篇直接判“证据不足”，并估算还要发多少篇才能判断。                                                 |
| **数字逐个核对**   | AI 写的总结里出现引擎结果里找不到的数字，会被要求重写一次；还不对就换回引擎自动生成的总结，并在页面上提示。 |
| **从相关到实验**   | 有苗头但证据不够的说法，生成 ABBA 交替的实验顺序，发完回填数据再判一次。                                    |
| **不用 AI 也能用** | 没有 API Key 时，表格导入、规则检验和实验处方照常可用，报告标明“未使用 AI”。                                |

## 五个平台的导入方式

| 平台    | 后台导出表格                                                 | 截图识别 | 粘贴表格 | 自动识别的列（节选）                                             |
| ------- | ------------------------------------------------------------ | -------- | -------- | ---------------------------------------------------------------- |
| 小红书  | 可用：单篇笔记导出（每篇一个文件，可多选），已用真实文件核对 | 可用     | 可用     | 曝光、观看、封面点击率、观看时长、净涨粉（单篇导出没有点赞收藏） |
| 抖音    | 未核实                                                       | 可用     | 可用     | 播放、点赞、评论、收藏、完播率、时长                             |
| B 站    | 未核实                                                       | 可用     | 可用     | 播放、点赞、投币、收藏、弹幕                                     |
| 公众号  | 有公开资料描述后台可导出                                     | 可用     | 可用     | 阅读、分享、在看、点赞、收藏                                     |
| YouTube | 有公开资料描述 Studio 可导出 CSV                             | 可用     | 可用     | Views、Watch time、CTR、Subscribers                              |

- 表格支持 CSV、TSV 和 .xlsx；中文 Excel 存的 GBK/GB18030 编码会自动识别。“1.2万”“10万+”“12.5%”“0:18”“3天前”“07-01 20:15”都能读。
- 截图识别需要配置 AI。长截图会在浏览器里切成几段，重叠部分在服务端合并。截图只用于这一次识别，不保存。
- **列对应**：上传表格或粘贴后，先显示每一列被当作什么（标题、发布时间、某个指标或不使用），附几行示例值。认不出的列可以手动指定，表头不在第一行也可以改。确认导入后，这种表头的对应关系会被记住，下次同样的导出会自动套用。
- **单篇导出可以多选**：小红书数据中心导出的是每篇笔记自己的数据，每篇一个 .xlsx（第一个工作表是这篇的合计，后面是按天、按小时的趋势）。一次选多个文件，每个文件算一篇；标题取自文件名，发布时间按趋势里最早的记录估算，导入后在表格里核对。文件丢了扩展名也能认出是 Excel。
- **账号汇总表会被拦下**：数据中心最容易找到的导出往往是账号整体的数据，比如小红书的“近30日观看数据”（第一个工作表是合计，后面每个工作表是一项指标的每日趋势）。这类表没有逐篇的行，导入时会直接说明，并提示去找按作品列出的明细，而不是让人对着它做列对应。
- 表头带“(%)”的列，里面的数字一律按百分数读：“封面点击率(%)”里的 0.8 是 0.8%，不是 80%。
- 无论哪种方式，导入后都要在表格里核对确认才能解剖；AI 没把握的格子会标黄。

**验证程度**：

- 每个平台都有导入测试，但测试用的表头是按公开资料和常见写法构造的，**不是真实导出文件**。例外是小红书：指标名按真实数据中心截图核对过，单篇笔记导出和“近30日观看数据”导出都用真实文件验证过（测试里用的是同样的版式和编造的数字）。单篇导出只有曝光、观看、点击率、观看时长、完播率和涨粉，没有点赞、收藏、评论，需要这些就用截图识别。
- 公开资料和开源代码里都没有找到这五个平台导出文件的确切列名。
- 所以真实导出能否导入，靠的是“列对应”：自动识别不了的列，手动指定一次就行。

## 快速开始

需要 Node.js 22.13 及以上版本（使用内置的 `node:sqlite`）。

```bash
npm install
cp .env.example .env      # 填写 ANTHROPIC_API_KEY 才会启用 AI；不填也能做规则检验
npm run dev               # http://127.0.0.1:8793
```

打开页面后选平台，可以先点“合成示例”生成一个示例账号体验：数据里预埋了两条真规律（问句标题、教程类收藏）和两个陷阱（露脸封面集中在涨粉期、一篇 25 倍的爆文），页面会一直标注“合成示例数据”。

## 统计方法

| 创作者数据的坑 | 引擎的处理                                                                         |
| -------------- | ---------------------------------------------------------------------------------- |
| 长尾分布       | 计数类指标取 log2，比较中位数，置换检验（2000 次）和自助法 95% 区间                |
| 账号成长       | 因变量用“相对表现”：这篇减去前后各 5 篇的中位数；再看前后两段时间方向是否一致      |
| 单篇爆文       | 去掉最火的一篇重算                                                                 |
| 样本太少       | 每组至少 5 篇；不够就估算每组需要的篇数（80% 功效，5% 显著性，中位数效率折算 π/2） |
| 多重比较       | 所有检验统一做 Benjamini–Hochberg 校正                                             |
| 混杂           | 按选题（没有选题标签时按内容形式）分层，多数层方向相反就判“存疑”                   |
| 数据未成熟     | 发布不满 7 天的内容不计入                                                          |

判决规则（探索阶段的阈值，见 `src/server/engine/analyze.ts` 的 `thresholds`）：

- **成立**：校正后 q ≤ 0.10，方向与说法一致，并且去掉最火一篇、前后两段、分层三项检查都通过。
- **存疑**：q ≤ 0.10 但有一项检查不稳；或者单独看 p < 0.2 且方向一致。
- **证据不足**：每组不到 5 篇，或者区间太宽、看不出结论。
- **不成立**（玄学墓地），死因有五种：
  - 一篇爆文撑起来的
  - 其实是涨粉期的功劳
  - 同时检验太多条，侥幸显著
  - 在你的数据里正好相反
  - 两组几乎没有差别（区间在 ±25% 以内）

## 引擎评测

`npm run eval:engine -- --seeds 40` 会在 5 个平台各生成 40 个合成账号（每个 60 篇），只跑规则检验，不调用 AI。最近一次结果：

| 指标                                            | 结果               |
| ----------------------------------------------- | ------------------ |
| 预埋的真规律被判为成立                          | 91.9%（331/360）   |
| 判为成立的结论里，假的占比（错误发现率）        | 9.3%（34/365）     |
| 没有效果的说法被判为成立                        | 1.1%（34/3000）    |
| 露脸封面陷阱被判为成立                          | 0.5%（1/200）      |
| 露脸封面陷阱被识破为“涨粉期的功劳”              | 80.5%（161/200）   |
| 单篇爆文陷阱被判为成立                          | 0%（0/200）        |
| 对照：直接比平均数（高 20% 就算），假说法被当真 | 39.7%（1096/2760） |
| 对照：直接比平均数，露脸陷阱被当真              | 84.5%（169/200）   |

**这些都是合成数据上的结果**：数据的生成方式由我们设定，只能说明引擎在这些已知陷阱上的行为符合设计，不代表在真实账号上的准确率。真实账号上的效果需要试点验证。

## 实验追踪

报告里的“实验处方”可以一键开始。开始那天之后发布的内容自动算进实验。发完一轮并且数据稳定后，把最新数据导入、确认，在“实验”页核对：

- 每篇的 A/B 从它自己的标题和标签判断（读不出时按计划推定，并标明“按计划推定”），同时列出是否按计划执行。
- 比较的是“相对同期表现”，开始前的内容只用来算同期水平。
- 实验是事先定好的单个检验，不做多重比较校正，显著性水平 0.1；每组至少 4 篇已满 7 天的内容才下结论。
- 结论有四种：实验支持、实验不支持（方向相反，或两组差别在 ±25% 以内）、还看不出（给出大约需要的篇数）、等待数据。

合成数据上的表现（每个账号开始后约 24 篇，每种情况 100 个账号）：

| 情况                       | 实验支持 | 实验不支持 | 还看不出 | 等待数据 |
| -------------------------- | -------: | ---------: | -------: | -------: |
| 真规律（问句标题，1.8 倍） |       82 |          0 |       16 |        2 |
| 无效说法（感叹号）         |        4 |          3 |       80 |       13 |
| 无效说法（周末发）         |        5 |          8 |       86 |        1 |
| 无效说法（标题带表情）     |        4 |          7 |       84 |        5 |

## AI 调用

使用 Claude（`@anthropic-ai/sdk`）：

- **结构化输出**：`beta.messages.parse` + Zod，四个环节分别是截图识别、内容标注、猜想、总结与反方意见。
- **模型**：默认全部用 `claude-opus-5-5`，effort 默认 `medium`。可以用 `VA_VISION_MODEL`、`VA_LABEL_MODEL`、`VA_REASON_MODEL` 按环节换模型。
- **请求设置**：
  - 系统提示开启提示缓存。
  - 开启服务端拒答回退（`fallbacks: "default"`）。
  - `refusal` 和 `max_tokens` 都有明确的错误提示。
- **防注入**：截图里的文字和标题都按数据处理，提示词明确要求忽略其中的指令。
- **最小发送**：只发送标题、截图和统计结果，不发送账号凭证。截图只用于本次识别，不保存。

**成本（估算，未用真实调用验证）**：按 Opus 5.5 的价格（每百万 token 输入 $4、输出 $20），一次 60 篇的 AI 解剖（标注 + 猜想 + 总结）约 $0.3–0.5，截图识别每张约 $0.05。应用内“设置”页会记录每次调用的实际 token 和估算费用，以账单为准。

## 开发

```bash
npm run typecheck
npm run lint
npm test                      # 导入、统计、引擎、AI 流程（假模型）、API
npm run eval:engine           # 合成账号评测，不调用 AI
npm run build && npm start
```

代码结构：

- `src/shared/`：平台定义（指标、列名别名、导入方式）和共享类型。
- `src/server/import/`：表格解析、编码、中文数字与日期、列识别与列对应。
- `src/server/engine/`：统计、特征、20 条说法、判决、实验处方与实验核对、总结模板。
- `src/server/guards/`：AI 数字核对。
- `src/server/ai/`：Claude 调用、提示词、截图识别、标注、猜想、总结。
- `src/server/synth/`：带标准答案的合成账号。
- `src/server/db/`：SQLite 与版本化迁移。
- `src/client/`：React 界面。
- `src/cli/evalEngine.ts`：引擎评测。

## 局限与下一步

- **AI 环节没有用真实模型跑过**：这次开发环境没有可用的 API Key，截图识别、标注、猜想和总结都是用假模型测试的。配好 Key 后，建议先用一组自己的截图试一次，核对识别准确率和实际费用。
- **真实导出文件没有核对过**：五个平台的列名都没有拿到真实样本，自动识别不了时用“列对应”手动指定。
- **几十篇的样本，多数说法会是“证据不足”**：这是诚实的结果，实验处方就是为此准备的。
- **实验需要几周**：一轮 8–12 篇，加上每篇 7 天的稳定期，结论通常要一个月左右。
